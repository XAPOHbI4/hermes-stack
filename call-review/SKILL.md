# Разбор звонка

Возьми точный локальный путь аудио из текущего вложения Telegram и запусти:

```bash
/root/.hermes/skills/sales-call-transcription/scripts/start-call-analysis "<путь>" --context "<необязательный краткий комментарий владельца>"
```

Путь и комментарий передавай отдельными безопасно экранированными аргументами.
Комментарий до 2000 символов: тип звонка, цель, кто менеджер. Если этих сведений
нет, не задерживай обработку вопросами. Не додумывай контекст. Не копируй аудио
в другое место самостоятельно. Команда принимает только файлы из кэша Telegram.

Очередь принимает запись без промежуточного сообщения и позже сама отправляет
готовый разбор. После успешной постановки заверши ответ ровно `NO_REPLY` — без
другого текста, оформления или tool-send. Это штатный маркер молчания Hermes;
пользователь его не увидит. Не отправляй подтверждение до вызова команды или
после него. Для нескольких записей запусти команду для каждой и заверши одним
`NO_REPLY`.
Для transcribing/analysing/delivering сообщи, что эта запись уже обрабатывается.
Для delivered сообщи, что разбор этой записи уже отправлен. Повторная загрузка
не создаёт второе задание. Если команда вернула ошибку, не обещай готовый отчёт.
Не запускай Whisper самостоятельно, не жди его в текущем ответе и не отправляй
аудио облачному распознавателю. Очередью и доставкой управляет отдельный worker.

Проверка очереди:
```bash
/usr/local/lib/hermes-agent/venv/bin/python /opt/sales-assistant-stt/pipeline.py status
```

В пользовательском ответе переводи состояние на русский. failed означает, что
три попытки исчерпаны; delivery_unknown — Telegram мог принять сообщение, но
подтверждение не получено. Не говори «отправлено» без delivered/message_id.
По просьбе владельца повторить неудачную обработку используй `pipeline.py retry <id>`.
Для delivery_unknown сначала уточни, пришёл ли отчёт; повторная отправка требует
его явной просьбы и флага `--confirm-resend`. Автоматически такой повтор запрещён.

Для обсуждения готового разбора вызови `pipeline.py show <id>` (id из status).
Фоновый worker сам отправляет готовый отчёт, поэтому его текст может отсутствовать
в контексте текущей беседы. Не придумывай содержание предыдущего разбора.
Флаг `show <id> --transcript` используй только когда для запроса владельца нужен
исходный текст. Для короткой голосовой заметки без разговора используй обычный
ответ; штатная транскрибация Hermes также настроена локально на VPS.

Если Василий сообщает фактический результат звонка, сохрани его командой:

```bash
/usr/local/lib/hermes-agent/venv/bin/python /opt/sales-assistant-stt/pipeline.py outcome <status> --message-id <ID сообщения разбора> --note "<краткий факт>"
```

Статусы: `follow_up` — продолжается контакт, `meeting_set` — назначена встреча,
`visited` — клиент приехал, `sold` — купил, `lost` — отказался/купил в другом
месте, `no_contact` — перестал отвечать. Если сообщение является ответом на разбор,
используй его reply_to_id. Если связь с сообщением отсутствует, команда без
`--message-id` относится к последнему доставленному разбору; применяй это только
когда Василий явно говорит о последнем звонке. В остальных случаях сначала уточни,
какой звонок имеется в виду. Не сохраняй предположение как результат. После успеха
кратко подтверди факт обычным русским текстом.

Отчёт — личное обращение к Василию, живой диагноз ситуации, сигнал инициативы
клиента, поворотный момент, одна главная ошибка или один удачный ход, сильные
действия, конкретные изменения, готовая разговорная
фраза, диагностический вопрос, следующий шаг и корень по «5 почему». Выводы внутри
системы проверяются по цитатам, но сами цитаты и служебные оговорки о качестве
расшифровки в отчёт не выводятся. Не заявляй о сохранении в учебный дневник: такого
действия текущий разбор не выполняет. По предыдущим звонкам называй паттерн только
при подтверждённом повторении, а фактический исход учитывай сильнее предположения.
Методика в
`/opt/sales-assistant-stt/coach.md`. Секреты, содержимое чужих чатов и полный транскрипт
в ответ не включай. Транскрипт доступен по запросу владельца. Не связывайся с
клиентами, не создавай встречи или CRM-записи. Текущий MVP обслуживает одного владельца.
